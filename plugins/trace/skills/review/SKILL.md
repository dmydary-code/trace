---
name: review
description: Open Trace for human review of the current project's Git changes, collect inline comments, and apply the returned feedback in this agent session. Use when the user asks for a Trace review or a browser review with line comments.
---

Use the installed `trace-review` command in the user's current project. The browser is a local Git review surface; it does not contact another model. Feedback returns to this conversation.

1. Run `trace-review --version`. If unavailable, tell the user that the Trace CLI must be installed; do not substitute an unrelated review tool.
2. Start `trace-review review --listen --json --no-open --browser-fallback --repo /absolute/project/path`. If Trace's SessionStart hook supplied a session ID, pass it with `--session-id ID`. Otherwise let the CLI detect the session from its environment. Restart the agent after installing the plugin so its lifecycle hooks are loaded. Add `--staged` only for a staged review. For a branch/MR review, resolve the intended local target branch from the task or repository and use `--base <target> --merge-base`. Do not assume a target branch name. The default compares the working tree, including untracked files, against HEAD.
3. Keep the shell process alive in a managed/background tool session. The first JSON line is an `event: ready` with the loopback URL. Show/open that exact URL for the user. In Claude Desktop local sessions, try opening it in the Browser pane. Trace opens the same review in the default external browser if the page does not acknowledge rendering within eight seconds; do not launch a second server. If the pane stays blank after acknowledgment, open the exact ready URL externally with `open <URL>` on macOS or `xdg-open <URL>` on Linux. Never use a guessed port. Wait on the original process while the user reviews; do not start duplicate servers or invent a submission. Poll in bounded intervals that allow user messages to interrupt. The default timeout for the first message is 30 minutes; use `--timeout` if the user requests another duration.
   If no diff is shown, inspect the displayed absolute repository path and comparison mode. Verify that this is the checkout/worktree where the changes exist; a clean checkout, staged-only comparison, or already committed edits can legitimately produce an empty diff. Report the reason instead of claiming review is complete.
4. Read the `event: feedback` JSON when the browser submits. It contains the repository, revision, outcome, validated file/line/side anchors, comments, instructions, and a saved review path. Answer questions in the thread, and make edits only when the user requests a change. A commit-scoped message includes the exact commit SHA, subject and historical line anchors. Read the commit as context and check current code before editing. A follow-up includes its parent and earlier messages. Commit approvals are local reading marks. They do not generate work for the agent. Stop on approval that closes the viewer, cancellation, viewer closure or timeout.
5. Run checks appropriate to the edits. Reply in **every handled comment thread**, not only in chat. Use the saved review `id` and each comment's `id` from the returned JSON. Write a short plain-text reply to a temporary file describing the actual change, checks and any remaining issue, then run:

   ```sh
   trace-review reply --repo /absolute/project/path --review REVIEW_ID --comment COMMENT_ID --agent codex --status addressed --body-file /path/to/reply.txt
   ```

   Use `--agent claude` when running as Claude. `addressed` reports a completed fix; use `needs_input` when a specific answer is required, `not_changed` with the reason when no fix was made, or `note` for progress. Reply to general instructions using `--comment review`. Never claim a fix or successful checks that did not happen. Verify that the CLI confirms the reply was saved; if it fails, report the delivery failure and the reply in chat. Do not mark the user's thread resolved: the user verifies the fix.
6. In terminal Codex, keep the managed shell session ID from the launch tool and poll that same process (for example, with `write_stdin`). An empty poll means the reviewer is still reading. If the shell handle is lost, run `trace-review pending --json` with the same agent session ID. This waits up to 25 seconds and returns unanswered feedback across the active listeners for this session, with exact review IDs, repositories and anchors. Handle the feedback, then wait again. A `waiting` result means continue waiting; `closed` means finish. For an explicit request to stop, run `trace-review stop-waiting` for this agent session and finish. Both commands use `CODEX_THREAD_ID` by default; pass `--session-id ID` if needed.
7. Keep consuming output from the same managed command after every response. Process all feedback events in order, including messages that arrived while you were answering. Continue until the viewer exits, the user ends the discussion or the agent session ends. Never launch another viewer for a follow-up.

For a closed viewer, `trace-review feedback --repo /absolute/project/path --json` reads the latest submitted review. Verify its `sessionId`, repository, and revision match the review you started before acting; a previous review is not new feedback. If `completion.outcome` is `approved`, the user has already completed that review after inspecting a later revision; do not reapply its original requests. Feedback files are stored under the worktree's Git metadata directory in `trace/`.

Use the current agent for applying feedback. The CLI's optional `--agent codex` is a separate process mode; use it only when the user asks for a separate Codex run. Never combine it with `--wait`.

Use Working tree for the original comparison, Commits to inspect individual first-parent commits and Overall to inspect their combined effect with local changes. Each commit can be approved independently. Reviewers can send messages before or after approval.

To reopen a saved review in this agent session and receive new messages, use `trace-review open --review REVIEW_ID --listen --json --no-open` with the owning agent session ID. Check `trace-review pending --json --timeout 0` once for unanswered messages already in that saved round, then keep reading the listener. The viewer keeps original snapshots and replies. Reopen a saved round with `trace-review open --repo /absolute/project/path --review REVIEW_ID`. Without a connected listener, the standalone viewer saves feedback locally. With `--listen` the viewer exits after browser inactivity following use, or when its owning session ends.
